## 值对象 Value Objects 

有些对象是用于描述或计算事物的某些特征的。  

很多对象并没有概念上的标识(identity)。

跟踪实体的标识是必需的，但是为不是实体的对象也赋予标识则会影响系统性能，增加分析工作，使模型变得混乱，因为这样的话实体和值对象看起来就是一样的了。软件设计是一场面对复杂性的持久战。必须对这两种不同的对象加以区分，只在必要时才进行专门处理。  

然而，如果仅仅认识到这种对象不具有标识，那么就没有在我们的工具箱或词汇表中增加太多东西。事实上，这些对象具有自己的特征，对模型也有其重要意义。这些对象的作用在于对事物进行描述。  

因此：  

**当只关心某个模型元素的属性和逻辑时，应该将其归为值对象。让其表达属性的含义，并为其赋予相关的功能。将值对象视为不可变的。使所有操作都成为“无副作用函数”，从而不依赖于可变状态。不要为值对象赋予标识，从而避免维护实体时才需要的设计复杂性。**
